jp-evalb: Robust Alignment-based PARSEVAL Measures

An alignment-based alternative to evalb for constituency parsing evaluation when sentence boundaries and tokenization differ from the gold trees

NAACL 2024 Demo

Jungyeul Park1, Junrui Wang1, Eunkyul Leah Jo2,3, Angela Yoonseo Park1

1Department of Linguistics, The University of British Columbia, Canada 2Department of Computer Science, The University of British Columbia, Canada 3Faculté des Sciences et Ingénierie, Sorbonne Université, France

Paper (ACL Anthology) PDF arXiv Code

Abstract

We introduce an evaluation system designed to compute PARSEVAL measures, offering a viable alternative to evalb commonly used for constituency parsing evaluation. The widely used evalb script has traditionally been employed for evaluating the accuracy of constituency parsing results, albeit with the requirement for consistent tokenization and sentence boundaries. In contrast, our approach, named jp-evalb, is founded on an alignment method. This method aligns sentences and words when discrepancies arise. It aims to overcome several known issues associated with evalb by utilizing the ‘jointly preprocessed (JP)’ alignment-based method. We introduce a more flexible and adaptive framework, ultimately contributing to a more accurate assessment of constituency parsing performance.

How jp-evalb Works

evalb, the standard PARSEVAL implementation, requires the gold and system files to have the same number of sentences and the same terminal tokens; otherwise sentences are skipped or reported as errors. jp-evalb adds a linear-time alignment step before the usual constituent matching, borrowing the idea of sentence and word alignment from machine translation:

  1. Sentence alignment. Tokens L (gold) and R (system) are compared with spaces removed. Two sentences match if they are equal, or if they are similar (edit distance below 10% of the character length) and the next pair also matches. Otherwise consecutive sentences on the shorter side are accumulated until the next pair matches, so m:n segmentations are merged into one aligned pair.
  2. Word alignment. Inside each aligned pair, tokens are matched in the same way; mismatching spans such as ca n't / can not are accumulated until the following tokens agree. A small per-language exception list of contractions and symbols handles frequent cases directly.
  3. Constituent matching. Constituents (label, start, end, aligned tokens) are extracted from both trees and a constituent counts as a true positive if label and aligned span agree, yielding the usual precision, recall and F scores, matched and crossing brackets, and POS tagging accuracy.

jp-evalb produces the same output columns as evalb. By default it keeps punctuation and all tokens, so bracket counts reflect the actual constituents and tagging accuracy is computed over every token; a legacy option (second line; COLLINS.prm is used if no parameter file is given) reproduces evalb exactly: 

python3 jp-evalb.py gold_parsed_file system_parsed_file
python3 jp-evalb.py gold_parsed_file system_parsed_file -evalb param.prm

Main Results

  • Exact evalb reproduction. On Section 23 of the English Penn Treebank, the -evalb legacy option produces exactly the same per-sentence results as the original evalb (e.g. sentence 2: recall 70.97, precision 73.33, 22 matched brackets, tagging accuracy 100.00), including cases evalb reports as Length unmatch or Words unmatch.
  • Punctuation-inclusive default. With punctuation counted, bracket scores are unchanged but tagging accuracy is over all tokens: for sentence 1 (8 tokens) jp-evalb reports 7/8 = 87.50 vs. evalb's 5/6 = 83.33.
  • All five evalb bug cases are scored. Sentences 1, 2 and 5 contain symbols treated as words; sentences 3 and 4 contain real word mismatches from inserted trace symbols (*-num). jp-evalb evaluates all of them without failure (table below).
  • End-to-end Korean parsing. On 148 gold sentences (4,538 morphemes) from BGAA0001 of the Korean Sejong treebank, the system pipeline (sjmorph.model segmentation + Berkeley parser) produced 123 sentences and 4,367 morphemes; jp-evalb aligns these mismatched sentences and morphemes and scores the parses.
  • Speed. On Penn Treebank Section 23 with matching sentences and words, the Python implementation takes about 4.5 seconds vs. less than 0.1 seconds for the C implementation of evalb; alignment itself is linear time.
