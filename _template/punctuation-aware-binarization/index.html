Punctuation-aware treebank tree binarization

Keeping punctuation as sibling nodes before binarizing Penn Treebank trees: a reversible pipeline that raises head-child prediction accuracy to 91.85%

arXiv 2025

Eitan Klinger1,†, Vivaan Wadhwa1,†, Jungyeul Park2,*

1Department of Computer Science, The University of British Columbia, Canada 2Culture Technology Research Institute, Korea Advanced Institute of Science & Technology (KAIST), South Korea

†Equal contribution   *Corresponding author

Paper (arXiv) PDF Code Resource (Zenodo)

Abstract

This article presents a curated resource and evaluation suite for punctuation-aware treebank binarization. Standard binarization pipelines drop punctuation before head selection, which alters constituent shape and harms head-child identification. We release (1) a reproducible pipeline that preserves punctuation as sibling nodes prior to binarization, (2) derived artifacts and metadata (intermediate @X markers, reversibility signatures, alignment indices), and (3) an accompanying evaluation suite covering head-child prediction, round-trip reversibility, and structural compatibility with derivational resources (CCGbank). On the Penn Treebank, punctuation-aware preprocessing improves head prediction accuracy from 73.66% (Collins rules) and 86.66% (MLP) to 91.85% with the same classifier, and achieves competitive alignment against CCGbank derivations. All code, configuration files, and documentation are released to enable replication and extension to other corpora.

Keywords Treebank binarization Punctuation Head-child identification Head finding Collins head rules Penn Treebank (PTB) CCGbank Constituency parsing Reversibility

Method

The transformation fpunct(T) (Algorithm 1 in the paper) visits every node in depth-first order and handles each punctuation child independently, in linear time:

  1. Determine its attachment direction: RIGHT if it precedes a non-punctuation child (e.g. opening quotation marks, parentheses; marked ▶), otherwise LEFT (e.g. commas, periods; marked ◀).
  2. Insert an intermediate node @X carrying that direction flag and attach the punctuation as a sibling of its neighboring constituent.
  3. Record the positional flag and a structural signature so the step can be undone.

The local restructuring rules (Figure 2 in the paper) are:

r1  (X ... nt_i punct▶ nt_j ...)              →  (X ... nt_i (@X punct▶ (@X nt_j ...)))
r2  (X ... nt_i ◀punct nt_j ...)              →  (X (@X (@X ... nt_i) ◀punct) nt_j ...)
r3  (X ... nt_i punct▶ nt_j ... ◀punct nt_k ...)
                                              →  (X ... nt_i (@X (@X punct▶ (@X nt_j ...)) ◀punct) nt_k ...)

Because every @X node carries a unique flag and signature, the inverse fpunct−1 removes all @X nodes and restores the original tree in linear time, so fpunct−1(fpunct(T)) = T. Punctuation attachment behavior is set in a configuration file, so the same procedure can be applied to other languages' treebanks (e.g. full-width Chinese and Japanese punctuation, Spanish ¿ and ¡).

Main Results

  • Better head-child prediction. On PTB Section 23, accuracy rises from 73.66% with Collins head rules and 86.66% with an MLP trained on punctuation-stripped trees to 91.85% with the same MLP on punctuation-aware trees (mean over five seeds; evaluation on the 84.3% of sentences whose dependency and constituency tokenizations align).
  • Lossless round trip. All transformed trees in the evaluated portion of the Penn Treebank were restored to their original configurations without loss of constituent labels, spans, or punctuation placement.
  • Compatibility with CCGbank. Against CCGbank derivations on PTB Section 23 (1,858 sentences with exact terminal alignment), the binarized trees reach F1 76.07% (precision 76.99%, recall 75.17%) with jp-evalb; many remaining mismatches come from CCGbank promoting appositive commas to top-level constituents.
